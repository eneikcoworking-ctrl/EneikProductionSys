# Audit Report: System Startup and Task Generation Failure

## Issue Description
The user reported that upon triggering a new flow (e.g. project creation), the system did not fully start up as expected. The only observable artifact created in the database was the initial wishlist item (`WishlistEntity`), but no corresponding tasks (`TaskEntity`) were generated.

## Root Cause Analysis

Based on an audit of the codebase, the issue originates from a mismatch between how initial wishlists are created during project generation and the strict validation requirements enforced by the task compiler.

### 1. Incomplete Wishlist Creation in `createProject`
When a new project is created via the `ProjectController` calling `ProjectFlowService.createProject`, an initial `WishlistEntity` is created based on the provided client brief:
```java
WishlistEntity firstWishlist = new WishlistEntity();
firstWishlist.setProjectId(saved.getId());
firstWishlist.setContent(initialWishlist.trim());
firstWishlist.setSource(WishlistSource.client);
firstWishlist.setStatus(WishlistStatus.pending);
wishlistRepository.save(firstWishlist);
```
As shown, the entity is only populated with `projectId`, `content`, `source`, and `status`.

### 2. Strict Definition of Ready (DoR) Enforcement
The task generation process is handled by `TechnicalLeadCompiler.createTaskFromWishlist`. Before any task is compiled or generated, the compiler invokes `validateDefinitionOfReady(WishlistEntity w)` to ensure the wishlist item meets strict formalized task requirements.

`validateDefinitionOfReady` enforces that the following fields MUST be present and valid:
*   `tocConstraintRef` (Step 1 - Bottleneck Check)
*   `leanValue` (Step 2 - Lean Classification, cannot be 'waste')
*   `jtbd` (Step 3 - Situation-Motivation-Result)
*   `sixSigmaMetric` (Step 4 - Escaped defects/success rate)
*   `dod` (Step 5 - Role-Grounded Definition of Done, must contain `BARCAN-TAG-XX`)
*   `acceptanceCriteria` (Step 7 - Given/When/Then scenario)

Because the initial wishlist generated by `createProject` entirely lacks these fields, `validateDefinitionOfReady` returns a list of validation errors.

### 3. Orchestration Abortion
When `validateDefinitionOfReady` encounters errors, it immediately throws an `IllegalStateException("Definition of Ready not met: ...")`.

During the continuous orchestration loop (`ContinuousOrchestrationService.continuousOrchestrate` calling `ProjectFlowService.orchestrate`), the system attempts to process `pending` wishlist items. When the compiler encounters the incomplete initial wishlist (or the identically incomplete environment bootstrap wishlist), the resulting `IllegalStateException` is thrown. This unhandled exception bubbles up, aborting the `orchestrate` loop entirely before any tasks can be successfully created and saved.

## Conclusion
The system stalls because the initial client wishlist item is not compliant with the `TechnicalLeadCompiler`'s "Definition of Ready". The compiler correctly refuses to process the incomplete item, throwing an exception that halts the orchestration loop, leaving the project in a state where only the initial wishlist exists and no tasks are ever generated.
