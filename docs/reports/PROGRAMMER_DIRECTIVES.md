## 2. Философский базис RAG-корпуса (D008, D010, D006)

- **`KARL_POPPER_01_FALSIFICATION_HARNESS` [D008 False green, Popper]:** Принцип фальсификации. Конфигурационные компоненты и санитарные рубежи не принимаются «на веру». Тестовый заслон обязан проверять граничные условия: обработку неожиданных исключений в `GlobalExceptionHandler`, корректное распознавание аномалий графа и застрявших токенов в `TocAnomalyDetector`, регистрацию дефектов и их атрибуцию в `DefectJournalService`. Тесты должны падать при искажении логики маппинга или игнорировании сбоев.
- **`ELVIN_GOLDMAN_16_LEVEL_OF_ABSTRACTION_LOCK` [D010 Data lineage loss, Goldman]:** Лок уровней абстракции и надежность цепочки происхождения данных (`ELVIN_GOLDMAN_01_RELIABILITY_CHAIN`). Инфраструктурные параметры и санитарные рубежи не должны размывать границы домена. `GlobalExceptionHandler` обязан отличать клиентские обрывы соединений (`ClientAbortException`) от системных аварий сервера без потери контекста. `DefectJournalService` фиксирует отказы фабрики как институциональные факты с сохранением точной цепочки причинности.
- **`DZHOZEF_RAZ_01_PROHIBITION_AS_CODE` [D006 Authorization ambiguity, Raz]:** Деонтический запрет как исключающая причина (`exclusionary reason`) и исполняемый код. Императивный запрет инженеру модифицировать рабочий код на Ступени 4 при проходящих тестах. В рантайме: деонтический запрет на неконтролируемый доступ CORS (`WebConfig`), защита учетных данных GitHub (`GithubConfig`), ограничение пула параллельных расписаний (`SchedulingConfig`).

## 3. Пакетный наряд по механизмам Секции XVIIб (Ступени 3–4: «Замер в рантайме, не правка кода»)

### А. Пул потоков планировщика задач: `SchedulingConfig` (ядро, пункт 428)
- **Действие:** Замерить распределение нагрузки по потокам планировщика (`poolSize = 10`), отсутствие голодания и конкуренции среди 41 аннотации `@Scheduled`.
- **Инварианты:**
  * Пул потоков жестко сконфигурирован и управляется единым владельцем (`SchedulingConfigurer`);
  * Периоды тиков таймеров не деградируют из-за исчерпания пула;
  * Отсутствие гонок между фоновыми задачами оркестрации.
- **Заслон:** Проверка конфигурации планировщика в рантайме, отсутствие голодания потоков. Исходный код НЕ ТРОГАТЬ.

### Б. Детектор аномалий потока ТОС: `TocAnomalyDetector` (пункт 429)
- **Действие:** Замерить работу детектора на обнаружение застрявших токенов и циклических повторных входов в граф выполнения ТОС.
- **Инварианты:**
  * Корректная изоляция узлов и выявление зависших стадий конвейера;
  * Сигналы аномалий передаются в `TocSentinelService` без искажения графа;
  * Детерминированное поведение при отсутствии аномалий (чистый граф).
- **Заслон:** `TocOptimizerTest`, `TocSentinelServiceTest`, `AnomalyReportFalsificationTest`. Исходный код НЕ ТРОГАТЬ.

### В. Реестр отказов фабрики: `DefectJournalService` (ядро, пункт 430)
- **Действие:** Замерить сохранение единой точки регистрации отказов и атрибуцию первопричин дефектов.
- **Инварианты:**
  * Любой фабричный отказ регистрируется как институциональный факт с категорией, описанием и таймстампом;
  * Цепочка причинности сохраняется без искажения (`ELVIN_GOLDMAN_01_RELIABILITY_CHAIN`);
  * Защита от дублирования записей об одном инциденте в рамках единого скоупа.
- **Заслон:** `DefectJournalServiceTest`, `DefectJournalRootCauseAttributionTest`, `LogScopeAndDefectJournalInusFalsificationTest`. Исходный код НЕ ТРОГАТЬ.

### Г. Централизованная конфигурация интеграции GitHub: `GithubConfig` (пункт 431)
- **Действие:** Замерить единый источник учетных данных (токен, организация, API base URL, флаг активности).
- **Инварианты:**
  * Учетные данные и адрес API централизованы (`RIGID_API_REFERENT`);
  * Отсутствие расхождений параметров между `GithubAccessService` и `GitHubPullRequestService`;
  * Корректная обработка флага отключенного GitHub без падения фабрики.
- **Заслон:** `GithubAccessServiceTest`, `GithubAccessServiceFalsificationTest`, `GitHubPullRequestServiceTest`. Исходный код НЕ ТРОГАТЬ.

### Д. Глобальный рубеж перехвата исключений: `GlobalExceptionHandler` (пункт 432)
- **Действие:** Замерить демаркацию клиентских сетевых обрывов (`ClientAbortException`, `Broken pipe`) от внутренних системных сбоев (500 Internal Server Error).
- **Инварианты:**
  * Непойманные исключения сериализуются в строгий RFC 7807 / проблемный JSON-ответ без утечки внутренних стеков в продакшене;
  * Сетевые обрывы клиентов логируются по санитарному уровню без ложной паники мониторинга;
  * Сохранение HTTP-статусов доменных исключений (`OperationalPolicyDeniedException` -> 409, 404, 400).
- **Заслон:** `GlobalExceptionHandlerTest`. Исходный код НЕ ТРОГАТЬ.

### Е. Веб-топология и CORS-политика: `WebConfig` (пункт 433)
- **Действие:** Замерить правила CORS, раздачу статических ресурсов панели оператора и заголовки безопасности.
- **Инварианты:**
  * Разрешенные методы (`GET`, `POST`, `PATCH`, `DELETE`) и заголовки строго согласованы с управляющей поверхностью;
  * Раздача статики панели не перекрывает API-эндпоинты контроллеров;
  * Защита от непреднамеренных междоменных утечек.
- **Заслон:** `WebConfigCorsTest`. Исходный код НЕ ТРОГАТЬ.
