4. **Основательность замеров:** Никакой искусственной спешки. Замеры телеметрии и верификация должны быть строгими и доказательными.

## 2. Философский базис RAG-корпуса

- `KARL_POPPER_01_FALSIFICATION_HARNESS` [D008, Popper]: фальсификация гипотез. Тесты-заслоны обязаны формулироваться как строгие опровержения (контрпримеры), выявляющие недопустимый дрейф или ложно-зеленый статус (`False green`).
- `ELVIN_GOLDMAN_16_LEVEL_OF_ABSTRACTION_LOCK` [D010, Goldman]: закон лок-уровня абстракции. Проектный барабан (`identifyDrum`) и буфер (`recommendedBufferCapacity`) изолированы проектной границей (`project-scoped`), тогда как емкость аккаунтов фабрики (`factory capacity`) контролируется семантикой диспетчера. Смешивание уровней без явного преобразования запрещено.
- `DZHOZEF_RAZ_01_PROHIBITION_AS_CODE` [D006, Raz]: деонтический запрет как исполняемый код и исключающая причина (`exclusionary reason`). Прямой запрет на правку исходного кода функционирующих механизмов фабрики на Ступени 4.

## 3. Пакетный наряд по механизмам Секции VII (Ступень 4: «Дописать запись замером»)

### А. `ConstraintIdentificationService`
- **Действие:** Замерить рантайм-поведение барабана и буфера.
- **Инвариант:** Проектная локализация задач (`findByProjectId...`), 0 кросс-проектных утечек.
- **Заслон:** Проверить `ConstraintIdentificationServiceTest` в Docker Maven. При необходимости добавить тесты фальсификации D010/D008. Исходный код сервиса НЕ ТРОГАТЬ.

### Б. `BottleneckDetectionService`
- **Действие:** Замерить детекцию узких мест оператора и агрегацию емкости аккаунтов.
- **Инвариант:** Емкость аккаунтов считывается один раз за вызов, синхронизирована с диспетчером (`isEnabled && (idle || busy)`), без N+1 по тегам.
- **Заслон:** Проверить `BottleneckDetectionServiceTest` и `BottleneckDetectionServiceFalsificationTest` в Docker Maven. Исходный код сервиса НЕ ТРОГАТЬ.

### В. `LaunchabilityConstraintService`
- **Действие:** Замерить логику постановки ограничения запускаемости (`product_not_launchable` в `WishlistEntity`).
- **Инвариант:** Единственное место постановки (`D006 BOUNDARY_TOPOLOGY`). Проверка подвижности попытки (`WishlistEntity::movable`), соблюдение кулдауна (45 мин) при повторной нездоровой пробе, маршрутизация строго на роль сборки `BARCAN-TAG-00`.
- **Заслон:** Разработать строгий тест-заслон `LaunchabilityConstraintServiceFalsificationTest` (покрытие инвариантов movable, cooldown, single owner, no double filing). Исходный код сервиса НЕ ТРОГАТЬ.

### Г. `TocSubordinationLever`
- **Действие:** Замерить механизм подчинения (`evaluateAndSubordinate`).
- **Инвариант:** Различие ранжирования приоритетов и подчинения (`D012 PRINCIPLED_INTEGRITY`). Предел системы не маскируется под рядовую задачу очереди.
- **Заслон:** Проверить `TocSubordinationLeverTest` и `TocSubordinationTruthTest`. Исходный код сервиса НЕ ТРОГАТЬ.
