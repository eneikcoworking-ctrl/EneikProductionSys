## 1. Инварианты оператора Дмитрия Ефремова

1. **Полная автономия:** Непрерывный автономный цикл без ожидания внешних подтверждений, согласований и пауз.
2. **Пакетный режим (Batching):** Work Order выдается строго пакетом на всю незакрытую секцию целиком. Начиная с Секции VII: TOC:
   - `ConstraintIdentificationService`
   - `BottleneckDetectionService`
   - `LaunchabilityConstraintService`
   - `TocSubordinationLever`
3. **Принцип ANTIGRAVITY_QUEUE (Ступени 3 и 4):**
   - **СТРОГО ЗАМЕР В РАНТАЙМЕ, А НЕ ПРАВКА КОДА.**
   - **КАТЕГОРИЧЕСКИЙ ДЕОНТИЧЕСКИЙ ЗАПРЕТ:** Запрещено модифицировать рабочий код сервисов при проходящих тестах!
   - Любое вмешательство в рабочий код фабрики допустимо исключительно при наличии воспроизводимого падающего теста, фальсифицирующего инвариант.
4. **Основательность замеров:** Никаких искусственных спешек и дедлайнов — замеры телеметрии и верификация должны быть основательными, доказательными и воспроизводимыми.

## 2. Философский базис RAG-корпуса (D008, D010, D006)

- **`KARL_POPPER_01_FALSIFICATION_HARNESS` [D008, Popper]:** Принцип фальсификации. Не искать подтверждений мнимого благополучия, а создавать строгие тесты-заслоны против ложно-зеленых состояний (`False green`). Любая гипотеза идеальности обязана быть опровержимой.
- **`ELVIN_GOLDMAN_16_LEVEL_OF_ABSTRACTION_LOCK` [D010, Goldman]:** Лок уровней абстракции и надежность эпистемической цепочки. Проектный барабан (`identifyDrum`) и буфер (`recommendedBufferCapacity`) жестко ограничены проектной границей (`project-scoped`), а емкость пула аккаунтов (`factory capacity`) выровнена по семантике диспетчера. Смешивание контекстов без явного моста строго запрещено.
- **`DZHOZEF_RAZ_01_PROHIBITION_AS_CODE` [D006, Raz]:** Деонтический запрет как исключающая причина (`exclusionary reason`) и исполняемый код. Императивный запрет инженеру переписывать функционирующий код на Ступени 4 при отсутствии падающего теста-заслона.

## 3. Пакетный наряд по механизмам Секции VII (Ступень 4: «Дописать запись замером»)

### А. `ConstraintIdentificationService`
- **Действие:** Замерить рантайм-поведение проектного барабана и буфера Литтла.
- **Инвариант:** Строгая изоляция задач по `projectId` (`findByProjectId...`), 0 кросс-проектных утечек.
- **Заслон:** Проверить `ConstraintIdentificationServiceTest` в изолированном Docker Maven. Исходный код сервиса НЕ ТРОГАТЬ.

### Б. `BottleneckDetectionService`
- **Действие:** Замерить детекцию заторов и чтение емкости пула аккаунтов.
- **Инвариант:** Единое обращение к емкости за такт, синхронность с диспетчером (`isEnabled && (idle || busy)`), отсутствие N+1 запросов.
- **Заслон:** Проверить `BottleneckDetectionServiceTest` и `BottleneckDetectionServiceFalsificationTest` в Docker Maven. Исходный код сервиса НЕ ТРОГАТЬ.

### В. `LaunchabilityConstraintService`
- **Действие:** Замерить постановку топологического ограничения запускаемости (`product_not_launchable` в `WishlistEntity`).
- **Инвариант:** Единственный эмитент ограничения (`AHILLE_VARTSI_03_BOUNDARY_TOPOLOGY` / D006). Проверка подвижности попытки (`WishlistEntity::movable`), соблюдение кулдауна (45 минут) между пробами, маршрутизация строго сборщику `BARCAN-TAG-00`.
- **Заслон:** Закрепить тестом-заслоном `LaunchabilityConstraintServiceFalsificationTest`. Исходный код сервиса НЕ ТРОГАТЬ.

### Г. `TocSubordinationLever`
- **Действие:** Замерить отсечение слак-задач при активном ограничении запускаемости (`evaluateAndSubordinate`).
- **Инвариант:** Разделение ранжирования и подчинения (`D012 PRINCIPLED_INTEGRITY`). Ограничение системы не маскируется под элемент общей очереди.
- **Заслон:** Проверить `TocSubordinationLeverTest` и `TocSubordinationTruthTest` (4-значная логика Белнапа). Исходный код сервиса НЕ ТРОГАТЬ.
