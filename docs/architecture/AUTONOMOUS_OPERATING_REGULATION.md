# Регламент совместной автономной работы: Antigravity & Claude

**Цель оператора:** Пользоваться идеально работающей автономной фабрикой ПО (`EneikProductionSys`), быть на 100% уверенным в качестве генерируемого кода продукта, без ручного подталкивания, зависаний и перегрузки ресурсов хоста.

---

## 1. Разделение суверенитета и ролей

| Параметр | Antigravity (Ведущий инженер $\mathcal{L}_2$) | Claude (Аудитор инвариантов $\mathcal{L}_1 / \mathcal{L}_3$) |
| :--- | :--- | :--- |
| **Главная обязанность** | Проектирование и кодовая реализация идеальной фабрики (Java 21, Spring Boot, PostgreSQL/H2). | Фальсификация инвариантов, аудит расхождений плана, надзор за моделью. |
| **Что делает** | Пишет архитектурный код ядра, ликвидирует категориальные ошибки, пишет юнит-тесты на законы, делает коммиты. | Проверяет репозиторий на соответствие 25 законам модели, обновляет `ENGINEERING_PHILOSOPHY_ACTION_PLAN.md` (держится / не держится), вычищает муду. |
| **Чего НЕ делает** | Не спамит философскими лекциями без кода, не трогает чужие задачи телеметрии. | Не правит продуктовый/заводской код вслепую, не запускает зависающие процессы, не спамит в чат отчётами без запроса. |
| **Среда работы** | Antigravity CLI / агентный рантайм. | `tmux` сессия `remotecli` в WSL 2 Ubuntu. |

## 2. Периодичность и ритм (Tact Time & Scheduling)

1. **Период такта:** **30 минут (1800 секунд)**.
2. **Задающий генератор:** За расписание отвечает **Antigravity** через системный инструмент `schedule(DurationSeconds=1800)`.
3. **Состояние Клода между тактами:**
   * Клод **не запускает** собственных бесконечных таймеров, циклов `/loop` или поллинга.
   * Клод находится в пассивном ожидании в терминале `remotecli` и просыпается по сигналу Antigravity.
4. **Структура 30-минутного такта:**
   * **Минуты 00–20 (Инженерный такт Antigravity):**
     1. Выбор очередного неработающего закона из плана (по порядку высвобождаемой ценности).
     2. Изучение точной механики дефекта в сервисах.
     3. Написание строгого архитектурного кода устранения (никаких костылей и заплаток).
     4. Написание изолированных модульных тестов на инвариант.
     5. Коммит в ветку `main`.
   * **Минуты 20–25 (Эстафета аудита):**
     1. Antigravity обновляет `docs/reports/CLAUDE_COORDINATION_NOTE.md` с описанием дельты коммита.
     2. Antigravity отправляет сигнал в `tmux` Клоду: запрос на верификацию плана по данному закону.
     3. Клод сверяет факт кода с инвариантом модели и молча обновляет статус в `ENGINEERING_PHILOSOPHY_ACTION_PLAN.md`.
   * **Минуты 25–30 (Синхронизация и переход):**
     1. Antigravity фиксирует состояние ресурсов (`free -m`, CPU, память).
     2. Запуск следующего 30-минутного таймера `schedule`.

## 3. Дорожная карта идеальной фабрики (Последовательность законов)

Работы ведутся строго по приоритету высвобождаемой ценности из Раздела III плана:

1. ✅ **Закон 4 (Предмет слияния):** Сведение предикатов приёмки к `hasRequiredMergeEvidence` в `ProjectFlowService` и `JulesDispatchService`. *(Выполнено, коммит `c344c23`)*.
2. ✅ **Закон 20 / S2 (Необратимость статуса):** Терминальный статус неизменяем. Защита 36 мест мутации статуса, строгий барьер в `TaskEntity.setStatus`, разделение на `initializeStatus` и `setStatus`. *(Выполнено, коммит `87d24f3`)*.
3. 🔄 **Закон 16 (Предмет ревью):** Задача входит в `TaskStatus.review` только если артефакт ревью уже существует или сессия ещё жива. Если сессия терминальна и артефакта нет — перевод в `failed` с освобождением слота.
4. ⏳ **Закон 13 (Ёмкость внешнего API):** Ключевание бюджета GitHub (`GitHubApiBudgetService`) по отпечатку токена, исключение глобального сброса лимитов всей фабрики из-за одного аккаунта.
5. ⏳ **Закон 15 (Готовность дизайн-цеха):** Снятие невыполнимого ожидания `ratio = 1.0` в brownfield; запуск по готовности конкретного среза или явному заказу.
6. ⏳ **Закон 8 & 9 (Вариантная функция и возврат бюджета):** Списание попыток компиляции только при наличии читаемого свидетельства об отказе внешнего компилятора, с возвратом попытки при локальном отказе проверки.
7. ⏳ **Закон 7 (Принадлежность ремонта):** Исключение потери ссылок `sourceTaskId` в ремонтных брифах, предотвращение создания мусорных задач без продуктового эпика.
8. ⏳ **Закон 18 (Неразрешённый вопрос):** Задачи с вердиктом `UNDECIDABLE` не замораживаются навсегда, а перезаказываются при изменении базиса.
9. ⏳ **Закон 1 (Единственная точка применения):** Устранение дублирования предикатов `carrier` и отправки в Jules.
10. ⏳ **Закон 22 (Демаркация сбоев):** Сбои инфраструктуры ($\mathcal{L}_1$) изолированы и никогда не порождают задачи на изменение клиентского кода ($\mathcal{L}_2$).

## 4. Гарантии стабильности и нулевой муды (Zero Muda & Anti-Freeze)

1. **Никакого неконтролируемого Docker:** Не запускать синхронные блокирующие команды `docker exec`, не стартовать контейнеры без явного указания оператора.
2. **Память хоста:** Потребление памяти WSL строго удерживается в пределах **< 1.0 GB** (свободно > 2.3 GB).
3. **Отсутствие словесного шума:** Отчёты оператору содержат только фактическую дельту кода, ссылки на файлы и состояние ресурсов.
4. **Молчаливое удаление сделанного:** Как только закон подтверждён кодом и тестами, он фиксируется в плане без мемориалов и длинных дневников.
