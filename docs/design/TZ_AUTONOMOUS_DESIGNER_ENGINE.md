## 1. ПОСТАНОВКА ПРОБЛЕМЫ И ЦЕЛЬ

### 1.1. Почему текстовые промпты («голые модели») терпят крах
Попытка поручить дизайн «голой модели» через текстовый системный промпт (даже самый подробный) приводит к систематическому браку:
1. **Слепота генерации:** Текстовая модель не видит пиксели, оптический вес заголовков и плотность верстки. Она генерирует CSS по статистической вероятности токенов, выдавая шаблонный Bootstrap/Tailwind пятилетней давности.
2. **Шаблонный мусор (AI-Slop):** Модели тяготеют к примитивным клише: фиолетово-синие градиенты, 3 одинаковые карточки с иконками в кружочках, размытые неоновые тени, центрированный мелкий текст и псевдотехнические надписи (Leica, GPS, статусы).
3. **Отсутствие зрительного контроля:** Без обратной связи через рендеринг и скриншоты модель не знает, что текст наехал на картинку или сломался на мобильном экране 375px.

### 1.2. Почему отключен внешний Google Stitch
Внешний Stitch (`stitch.googleapis.com/mcp`) требовал сервисный ключ Google Cloud Platform с привязанной картой и генерировал платные списания за вызовы API ($8 за сессию), не решая при этом проблему подстановки реальных ассетов проекта.

### 1.3. Цель разработки
Создать в составе ядра Фабрики **полноценную инженерную подсистему автономного дизайна (`Autonomous Designer Engine`)**, которая:
- Работает 100% автономно на инфраструктуре Фабрики без платных внешних API (0 рублей за генерацию).
- Обладает встроенным мультимодальным зрением (Playwright + Vision Feedback Loop).
- Создает дизайн-макеты уровня сайтов-миллионников (Stripe, Linear, Apple, Vercel, Mercury) для **любых типов продуктов и стартапов**, а не для одного сайта.
- Строго соблюдает деонтические запреты BARCAN-TAG-11 (чистота от визуального мусора).

## 2. АРХИТЕКТУРА И СОСТАВНЫЕ КОМПОНЕНТЫ ДИЗАЙНЕРА

Подсистема состоит из пяти взаимосвязанных функциональных блоков:

```
[Бриф нового проекта]
         │
         ▼
[1. Классификатор Архетипа & Компилятор Дизайн-Токенов (OKLCH / Fluid Typography)]
         │
         ▼
[2. Библиотека Композиционных Примитивов (Swiss Bauhaus & Linear Grids)]
         │
         ▼
[3. Семантический DOM-Синтезатор (HTML5 + Tailwind CSS + Ассеты ТЗ)]
         │
         ▼
[4. Мультимодальный Зрительный Контур (Playwright Dual-Viewport: 1440px / 375px)]
         │
         ▼
[5. Зрительный Аудитор & Итеративный Доводчик (Vision Quality Invariant)]
    ├── Ошибки/Смещение ──> Цикл правки (макс. 3 итерации) ──> На шаг 3
    └── Идеал (Score >= 9.2)
         │
         ▼
[Сертифицированный mockup.html + design_tokens.json -> Передача Джулсам]
```

---

### БЛОК 1: КЛАССИФИКАТОР АРХЕТИПА И КОМПИЛЯТОР ТОКЕНОВ (`DesignTokenCompiler`)
Агент не изобретает палитру наугад. Он компилирует строгую систему токенов под домен продукта:
1. **Матрица 4 архетипов продукта:**
   - **DevTools / Инфраструктура (Linear, Vercel):** Базовый холст `#08090C`, матричная сетка, изумрудные статусы, шрифт `JetBrains Mono` / `Geist Mono`. Герой — интерактивная консоль, код или архитектурная диаграмма. Людей на первом экране нет.
   - **FinTech / Enterprise (Stripe, Ramp):** Обсидиановые микроповерхности `#11141C`, границы `border-white/[0.07]`, ультра-четкие финансовые таблицы и графики.
   - **Editorial / Лидеры мнений (McKinsey, Pentagram):** Журнальная асимметрия, акцидентные заголовки `clamp(...)`. Фото основателя используется **строго если** оно приложено в `assets/` ТЗ. Если фото нет — строится типографическая композиция.
   - **Consumer / Hardware (Apple, Teenage Engineering):** Продукт в центре сцены, объемная глубина, тактильные микро-контроллеры, минимализм.
2. **Математические гарантии палитры:**
   - Контрастность текста по стандартам APCA / WCAG AAA (минимальный коэффициент контраста 7:1 для основного текста, 4.5:1 для вспомогательного).
   - Расчет гармонической типографической шкалы (модульное соотношение 1.25 / 1.333) через `clamp(min, preferred, max)` — нулевая зависимость от жестких пикселей.

---

### БЛОК 2: БИБЛИОТЕКА КОМПОЗИЦИОННЫХ СЕТОК (`LayoutPatternRegistry`)
Вместо шаблонных 3-колоночных сеток дизайнер использует проверенные архитектурные композиции сайтов-миллионников:
1. **Асимметричный разворот (Asymmetric Split 7/5 или 8/4):** Доминирующий визуальный блок слева/справа уравновешивается функциональным блоком справа/слева.
2. **Бенто-сетка с вариативными пропорциями (Bento Grid 2.0):** Неодинаковые ячейки с разным визуальным весом (главная метрика, интерактивный график, компактный кейс).
3. **Многослойный обсидиан (Layered Obsidian Depth):** Поверхности строятся ступенями: Canvas (`#08090C`) -> Card Surface (`#11141C`) -> Interactive Surface (`#161922`), разделенные 1px субпиксельными границами `border-white/[0.06]`.

---

### БЛОК 3: СЕМАНТИЧЕСКИЙ DOM-СИНТЕЗАТОР (`SemanticLayoutSynthesizer`)
Генерирует чистый, самодостаточный HTML5/Tailwind код:
- Семантические теги (`<header>`, `<main>`, `<section>`, `<article>`, `<nav>`).
- Полная доступность по клавише Tab (`focus-visible:ring-2`).
- Интеграция реальных ассетов проекта (пути к файлам из ТЗ). Никаких случайных AI-лиц.

---

### БЛОК 4: ЗРИТЕЛЬНЫЙ КОНТУР ВЕРИФИКАЦИИ (`PlaywrightVisionHarness`)
Дизайнер не сдает работу, пока не «увидит» ее глазами:
1. Контейнерный Playwright рендерит страницу на двух обязательных вьюпортах:
   - **Десктоп:** 1440px $\times$ 900px.
   - **Мобайл:** 375px $\times$ 812px (iPhone-стандарт).
2. Снимаются полноразмерные скриншоты высокого разрешения.
3. Замеряются метрики рендеринга:
   - Отсутствие горизонтального скролла на 375px (`scrollWidth == clientWidth`).
   - Отсутствие пустого белого экрана или сломанных картинок (HTTP 404).

---

### БЛОК 5: ЗРИТЕЛЬНЫЙ АУДИТОР И ИТЕРАТИВНЫЙ РЕФЛЕКС (`VisionAuditLoop`)
Скриншоты и DOM-структура валидируются по строгим деонтическим гейтам:
1. **Гейт детоксикации от шума (NO_COGNITIVE_VISUAL_NOISE):**
   - 0 фальшивых надписей оптики (Leica, 50mm, f/1.4).
   - 0 фальшивых GPS-координат и псевдостатусов.
   - 0 искажающих монохромных фильтров (grayscale, contrast-125) на портретах.
2. **Гейт композиционного качества:**
   - Иерархия: размер главного заголовка минимум в 2.5 раза больше подзаголовка.
   - Воздух: отступы между смысловыми блоками не менее 80px на десктопе, 48px на мобайле.
3. **Автоматический цикл доводки:**
   - Если аудитор обнаруживает дефект (например, слипшиеся блоки или плохой контраст), он формирует точный отчет с дельтами и запускает доводку кода.
   - Максимум 3 итерации. По достижении оценки $\ge 9.2/10$ макет получает статус `APPROVED`.

## 3. ИНТЕГРАЦИЯ В КОНВЕЙЕР ФАБРИКИ (`EneikProductionSys`)

1. **Сервисный слой бэкенда (`com.eneik.production.services.design`):**
   - Новый класс: `SovereignDesignSynthesisService.java`.
   - Внедрение в `DesignAssetService.java`:
     ```java
     // Вместо падения при отсутствии Stitch API ключа:
     if (requireImplementableHtml) {
         return sovereignDesignSynthesisService.synthesizeMockup(project, brief, context);
     }
     ```
2. **Хранение результатов:**
   - Черновик: `design/draft/{timestamp}-mockup/mockup.html`
   - Скриншоты: `design/draft/{timestamp}-mockup/desktop-1440.png`, `mobile-375.png`
   - Токены: `design/draft/{timestamp}-mockup/tokens.json`
   - После утверждения: перенос в `design/approved/{timestamp}-mockup/` и триггер создания задачи декомпозиции для Jules.

## 4. КРИТЕРИИ ПРИЕМКИ ДЛЯ ИНЖЕНЕРА (DEFINITION OF DONE)

1. **Функциональные критерии:**
   - При `stitch_enabled=false` или пустом `stitch_api_key` конвейер успешно генерирует полноценный `mockup.html`, скриншоты 1440px и 375px без единого внешнего платного запроса.
   - Ни один макет не содержит запрещенного визуального шума (Leica, GPS, фейковые лица, фиолетовые градиенты).
2. **Тестовое покрытие:**
   - Модульные тесты генератора токенов (`DesignTokenCompilerTest`).
   - Интеграционный тест зрительного контура с моком/рантаймом Playwright (`SovereignDesignSynthesisIntegrationTest`).
   - Фальсификационный тест Поппера: невозможность перехода в бесконечный retry при отсутствии внешних сервисов.
3. **Ресурсный инвариант:**
   - Тесты и сборка обязаны проходить в Docker Maven 3.9.9 (`-m 2g`) без превышения лимитов памяти.
