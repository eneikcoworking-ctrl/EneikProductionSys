## ГРУППЫ АГЕНТОВ

**Группа A — Проектирование, смысл, рамки и контракты**
* `TAG-00`, `TAG-01`, `TAG-02`, `TAG-09`, `TAG-12`
* Эти агенты определяют архитектурные границы, доменную модель, продуктовые приоритеты, ревью кода и машиночитаемые межсервисные контракты (OpenAPI/JSON Schema). Их решения первичны — остальные агенты работают в рамках, которые они задают.

**Группа B — Данные, логика и вычисления**
* `TAG-04`, `TAG-08`
* Отвечают за движение, хранение, миграции и интеллектуальную обработку данных.

**Группа C — Человеческий фактор и восприятие**
* `TAG-03`, `TAG-11`
* Отвечают за визуальный язык, дизайн-систему, доступность и клиентскую реализацию интерфейсов.

**Группа D — Надёжность, верификация и безопасность**
* `TAG-05`, `TAG-06`, `TAG-07`
* Гарантируют, что система работает, стабильно развернута в контейнерах, проверена автотестами и защищена от уязвимостей.

**Группа E — Регуляция и комплаенс**
* `TAG-10`
* Гарантирует соблюдение правовых и нормативных обязательств (GDPR, BGB, Data Privacy, право на удаление).

## ПРАВИЛА ОРКЕСТРАЦИИ

### 1. Основное правило автономности
Каждый агент автономно вытягивает из очереди задач **только задачи со своим тегом** либо участвует в последовательном многошаговом раунде философской фальсификации (`FalsificationCycleService`).

### 2. Разметка задач (Медиатор TAG-09 и Декомпозитор)
**TAG-09 (Медиатор)** и компилятор вишлистов отвечают за автоматическую и корректную разметку задач:

| Условие задачи | Назначаемый тег |
|----------------|-----------------|
| Параллельный старт Backend и Frontend (создание OpenAPI-спецификации) | `+ TAG-12` |
| Создание новой сущности или изменение границ домена | `+ TAG-01` |
| Реализация backend-логики и интеграционных слоев | `+ TAG-02` |
| Реализация пользовательского интерфейса и страниц | `+ TAG-11` |
| Изменение схемы БД, индексов, Flyway-миграций | `+ TAG-08` |
| Задача затрагивает ML-модели, эмбеддинги, скоринг | `+ TAG-04` |
| Задача затрагивает инфраструктуру, Docker Compose, деплой | `+ TAG-05` |
| Автоматизация тестов, регрессия, интеграционные прогоны | `+ TAG-06` |
| Аутентификация, авторизация, секреты, SAST/DAST | `+ TAG-07` |
| Хранение PII, права субъектов данных, GDPR, аудит | `+ TAG-10` |

### 3. Сквозной надзор
* **TAG-00 (Code Review)**: осуществляет автоматический сквозной аудит каждого Pull Request на соответствие 6 Sigma стандартам качества.
* **TAG-12 (API Contract)**: фиксирует статический машиночитаемый контракт ДО разделения работ между `TAG-02` и `TAG-11`.

## ГЛОБАЛЬНЫЙ DEFINITION OF DONE (DoD)

Задача считается завершённой во всей системе, если:

- [ ] Код прошёл автоматическое ревью `TAG-00` и получил подтверждение судейского контура.
- [ ] API-контракт зафиксирован в формате OpenAPI и согласован `TAG-12`.
- [ ] Автотесты написаны и проходят со 100% успехом (`TAG-06`).
- [ ] Схема базы данных оформлена в виде идемпотентной миграции Flyway (`TAG-08`).
- [ ] Секреты и токены изолированы, SAST-проверка чиста (`TAG-07`).
- [ ] UI-компоненты соответствуют дизайн-системе и WCAG AA (`TAG-03`, `TAG-11`).
- [ ] Проведен аудит соответствия нормам защиты данных (`TAG-10`).
- [ ] Контейнер `docker-compose` собирается и отвечает на JIT-рантайм зонд `200 OK` (`TAG-05`).
